1. تقييم الوضع، استئصال الأخطاء، والرؤية النظيفة (Assessment & Pure Vision)

التشخيص والتنقية

بعد التدقيق التحليلي لكود وقواعد بيانات النظام، تبين وجود فكرة تجارية ومحاسبية ممتازة، ولكنها كانت محاطة بأخطاء معمارية موروثة قاتلة. تم اتخاذ قرار حاسم باستئصال كافة الممارسات الخاطئة وبناء النظام على معايير حديثة 100%:

المحور الوضع الموروث القديم (المستأصل ❌) المعيار المعماري النظيف الجديد (المعتمد ✅)
هيكلية الكود والملفات ملف متحكم واحد controller.php يحتوي على 4,712 سطراً يدير كل شيء، مع 80 ملفاً مبعثراً في المجلد الرئيسي. معمارية Clean Modular MVC مفصولة؛ طبقة الخدمات (Services)، طبقة النماذج (Models)، وطبقة القوالب (Views).
محرك قاعدة البيانات محرك MyISAM القديم بدون معاملات ذرية (No ACID)، مع قفل الجدول بالكامل عند كل عملية بيع (Table Locks). محرك `InnoDB` حصرياً لدعم المعاملات الذرية (Commit/Rollback)، المفاتيح الأجنبية، وقفل السطور FOR UPDATE.
احتساب أرصدة المخازن حساب الرصيد عبر حلقة تقرأ كل حركات المتجر من تاريخ إنشائه وتجمعها في PHP عند كل مسحة باركود للكاشير! جدول حركات المخزون اللحظية المفهرس `stock_moves` برصيد متحرك مستمر يُستعلم في أجزاء من الميلي ثانية.
تقارير الجرد والحركات أوامر TRUNCATE TABLE كارثية تحذف بيانات تقارير الفروع الأخرى عند مجرد فتح الصفحة من أي مستخدم. استعلامات تجميعية مباشرة (Direct Aggregations) بدون تفريغ جداول أو التأثير على المستخدمين المتزامنين.
أمان الاستعلامات و SQL دمج مباشر لمتغيرات $_GET و $_POST داخل نصوص الاستعلامات (SQL Injection عالي الخطورة). اعتماد الاستعلامات المجهزة حصرياً (PDO Prepared Statements) مع فحص وتعقيم صارم لكافة المدخلات.
أمان كلمات المرور تشفير بـ md5() الضعيف والمهجور بدون Salt. تشفير عسكري حديث بخوارزمية `Bcrypt` عبر password_hash() مع حماية من هجمات القاموس.

2. المعمارية الهندسية الحديثة (Clean Modular MVC & Service-Repository Pattern)

Architecture

تم اعتماد معمارية متعددة الطبقات (Multi-Layered Architecture) تفصل تماماً بين واجهة العرض، منطق الأعمال، وطبقة البيانات:

1. طبقة النواة (Core Framework)

Foundation

تدير الاتصال الآمن بقاعدة البيانات (PDO)، إدارة الجلسات وصلاحيات الأدوار (RBAC)، رموز الحماية من التزوير (CSRF)، وفئات التسجيل والمساعدة.

2. طبقة الخدمات (Service Layer)

Business Logic

تحتوي على كافة الحسابات والمنطق التجاري: دورة البيع، توليد القيود المزدوجة، قفل التزامن للفواتير، واحتساب متوسط التكلفة المرجح.

3. طبقة النماذج (Model Layer)

Data Access

تتعامل مباشرة مع جداول قاعدة البيانات عبر Prepared Statements، وتوفر دوال CRUD المعيارية مع القيود المرجعية والفهارس.

4. طبقة الواجهات (View Layer)

UI / Templates

قوالب HTML5/CSS3 نقية لا تحتوي على أي كود استعلام SQL؛ تتلقى البيانات الجاهزة من الخدمات بنظام admin-pro المتناسق.

4. النواقص والوظائف المعززة التي أضيفت للنظام (Gap Analysis & Enterprise Features)

المزايا الجديدة المضافة

لضمان جاهزية النظام لمنافسة كبرى أنظمة الـ ERP ونقاط البيع في مصر والشرق الأوسط، تم تضمين الخصائص المتقدمة التالية:

باركود الموازين الإلكترونية

سوبرماركت ولحوم

فك وتفكيك الباركود الوزني تلقائياً (الذي يبدأ بـ 99 أو 20)؛ حيث يستخرج كود الصنف، الوزن الصافي، والسعر الإجمالي تلقائياً ويضيفه لسلة المشتريات.

تتبع الباتشات والصلاحيات

Lot & Expiry

ربط الواردات برقم تشغيلة وتاريخ صلاحية محدد، مع تنبيهات مسبقة قبل انتهاء الصلاحية بـ 60 و 30 يوماً لمنع الخسائر المخزنية.

تقرير أعمار الديون (Debt Aging)

إدارة السيولة

تصنيف مديونيات العملاء ومستحقات الموردين إلى فترات زمنية (أقل من 30 يوماً، 60 يوماً، 90 يوماً، وأكثر من 120 يوماً) مع مؤشرات مخاطر التحصيل.

سجل التدقيق والرقابة (Audit Trail)

الرقابة الداخلية

توثيق تلقائي لكافة الإجراءات الحساسة (حذف فواتير، تعديل أسعار، فتح درج النقدية، أو تطبيق خصومات استثنائية) باسم المستخدم ووقت المعاملة الدقيق.

مستويات التسعير المتعددة

جملة وقطاعي

دعم سعر بيع قطاعي، سعر بيع جملة، وسعر نصف جملة لكل صنف، مع تطبيقه آلياً حسب نوع العميل المسجل.

التقييم المالي للمخزون

Weighted Average

احتساب التكلفة الفعلية للأصناف بناءً على المتوسط المرجح التلقائي عند كل فاتورة شراء، مما يعطي أرباحاً صافية حقيقية 100%.

8. نموذج قاعدة البيانات المحدث وجداول الحركات اللحظية (Database & Unified Ledgers)

InnoDB Data Model

تم تحويل قاعدة البيانات بالكامل إلى محرك `InnoDB` وإضافة جداول الحركات اللحظية المفهرسة لمنع البطء نهائياً: 

-- جدول حركات المخزون اللحظية الموحد (Stock Moves Ledger)
CREATE TABLE IF NOT EXISTS `stock_moves` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT,
  `item_id` int(11) NOT NULL,
  `store_id` int(11) NOT NULL,
  `move_type` enum('in','out','transfer_in','transfer_out','adjustment') NOT NULL,
  `reference_type` enum('sale','purchase','return','transfer','opening') NOT NULL,
  `reference_id` varchar(100) NOT NULL,
  `quantity` decimal(12,3) NOT NULL,
  `unit_cost` decimal(12,2) NOT NULL,
  `balance_after` decimal(12,3) NOT NULL,
  `created_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_item_store` (`item_id`, `store_id`),
  KEY `idx_ref` (`reference_type`, `reference_id`),
  KEY `idx_date` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- فهارس قفل التزامن للفواتير السريعة
ALTER TABLE `sales` ADD INDEX `idx_sales_inv_store` (`invoice_No`, `storeid`);
ALTER TABLE `items` ADD INDEX `idx_items_barcode` (`barcode`);

9. الأمان، التشفير، وحوكمة الصلاحيات (Security, Cryptography & RBAC)

الأمان والرقابة
  • الاستعلامات المجهزة حصرياً (PDO Prepared Statements): القضاء التام على ثغرات الحقن (SQLi) في كافة العمليات.
  • تشفير Bcrypt: حماية كلمات مرور الموظفين بخوارزمية password_hash() القياسية.
  • حماية النماذج ضد CSRF: توليد رموز أمان مشفرة في كل نموذج وتمريرها آلياً مع مكالمات AJAX.
  • إغلاق ثغرة التخطي (EAR): إضافة exit(); بعد كافة أوامر التوجيه في Auth.php.
  • حوكمة الصلاحيات (RBAC): منع الكاشير من فتح تقارير الأرباح أو قيود اليومية وإعادته تلقائياً لشاشة البيع.
  • سجل التدقيق (Audit Logging): توثيق كل حركة حذف أو تعديل أو فتح درج نقدية في جدول audit_logs.
